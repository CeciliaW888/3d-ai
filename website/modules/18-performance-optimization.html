Day 18 — Performance Optimization for Web 3D A beautiful 3D scene that runs at 8 FPS ships nothing. Learn to measure, diagnose, and fix the real bottlenecks.

Why Web 3D Gets Slow

🚧
The #1 bottleneck is draw calls — not polygon count. Every separate mesh with a separate material costs a draw call. Most devices stall above 200–500 draw calls per frame. 500 separate trees = 500 draw calls. One instanced tree mesh = 1 draw call.

The four main causes of slow 3D on the web:

  • Too many draw calls — each mesh/material pair triggers a GPU state change
  • Too many polygons — every triangle is processed every frame
  • Too much texture memory — uncompressed 2048×2048 RGBA = 16 MB of VRAM
  • JavaScript overhead — your animation loop shares the main thread with the browser

Profiling: Measure Before You Fix

// Add the Stats panel (FPS, ms/frame, memory)
import Stats from 'three/addons/libs/stats.module.js';
const stats = new Stats();
document.body.appendChild(stats.dom);

// Check draw calls in real time
setInterval(() => {
  console.log('Draw calls:', renderer.info.render.calls);
  console.log('Triangles:', renderer.info.render.triangles);
}, 2000);

function animate() {
  requestAnimationFrame(animate);
  stats.begin();
  renderer.render(scene, camera);
  stats.end();
}

Spector.js (Chrome extension) captures a single WebGL frame and shows every draw call, shader, and texture. Install from the Chrome Web Store and click the extension icon while your scene is running. The draw call count is your optimization baseline.

InstancedMesh: 1,000 Objects, 1 Draw Call

import * as THREE from 'three';

const count = 1000;
const geometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
const material = new THREE.MeshStandardMaterial({ color: 0x0d9488 });

// InstancedMesh renders all 1000 copies in ONE draw call
const mesh = new THREE.InstancedMesh(geometry, material, count);

const matrix = new THREE.Matrix4();
for (let i = 0; i < count; i++) {
  matrix.setPosition(
    (Math.random() - 0.5) * 40,
    (Math.random() - 0.5) * 40,
    (Math.random() - 0.5) * 40
  );
  mesh.setMatrixAt(i, matrix);
}
// Required: tell Three.js to upload the matrix buffer to the GPU
mesh.instanceMatrix.needsUpdate = true;

scene.add(mesh);
// renderer.info.render.calls: 1 (vs 1000 for separate Mesh objects)

Optimization Checklist

1
Audit draw calls first

Log renderer.info.render.calls. If over 200, draw call reduction should be your first move — not polygon reduction.

2
Use InstancedMesh for repeated objects

Trees, rocks, coins, bullets, particles — anything rendered multiple times. One InstancedMesh per geometry+material pair.

3
Merge static geometry

Combine floor tiles, walls, and terrain chunks using mergeGeometries() from three/addons/utils/BufferGeometryUtils.js.

4
Compress assets

Run GLB files through Draco compression. Use WebP or KTX2 for textures. A 10 MB GLB can compress to under 2 MB.

5
Lazy-load distant objects

Only add a model to the scene when the camera is within a threshold distance. Remove it when the camera moves away.

6
Check frustum culling is on

Three.js skips objects outside the camera frustum by default (mesh.frustumCulled = true). Never set it to false unless you have a specific reason.
