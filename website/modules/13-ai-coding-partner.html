Day 13: AI as Your 3D Coding Partner

Use Claude, ChatGPT, and GitHub Copilot to write Three.js and React Three Fiber code faster — and learn how to spot the mistakes they make.

Today's insight: AI coding assistants are most useful in 3D when you give them full context up front — your Three.js version, your project setup, and the exact visual outcome you want. Vague prompts produce generic boilerplate; specific prompts produce working scenes.
5 Copy-Pasteable Prompt Templates
Template 1 — Basic Three.js scene 
I'm using Three.js r168 with a Vite + vanilla JS setup.
Write a complete scene with:
- A WebGLRenderer that fills the window and resizes correctly
- A PerspectiveCamera at position (0, 2, 5)
- An ambient light (intensity 0.5) and a directional light with soft shadows
- A rotating metallic sphere using MeshStandardMaterial
- An animation loop using requestAnimationFrame
Include a resize event listener and dispose cleanup.
Template 2 — React Three Fiber component 
I'm using React Three Fiber with @react-three/drei.
Write a self-contained React component called <ProductViewer> that:
- Loads a GLB file from /models/shoe.glb using useGLTF
- Shows a Suspense fallback with a spinning placeholder cube
- Uses OrbitControls (from drei) with damping enabled
- Adds an Environment preset="city" for lighting
- Accepts a `color` prop and applies it to the first MeshStandardMaterial
The component should be exported as default.
Template 3 — GLSL shader 
I'm writing a Three.js ShaderMaterial.
Write a vertex and fragment shader pair that creates an animated wave effect.
The vertex shader should displace Y using sin(position.x * frequency + time) * amplitude.
The fragment shader should color with a gradient: deep blue at base to white at peaks.
Include uniforms: time (float), frequency (float), amplitude (float).
Show how to pass these when creating the ShaderMaterial.

Common AI Pitfalls in Three.js

1
Removed APIs

Models trained before r125 may suggest THREE.Geometry (removed) or geometry.faces. Always check THREE.REVISION in the console and the migration guide.

2
Invented methods

AI sometimes generates plausible-sounding but non-existent calls like mesh.setMaterial(). If you get TypeError: x is not a function, check the Three.js docs directly.

3
Wrong import paths

AI may write 'three/examples/jsm/controls/OrbitControls' when newer Three.js uses 'three/addons/controls/OrbitControls.js'. These differ between Three.js versions.

4
Stale R3F patterns

React Three Fiber evolves quickly. Old forum posts and AI output may suggest deprecated extend usage or outdated hook signatures. Always verify against the official R3F docs.

Always verify AI-generated Three.js code by checking THREE.REVISION in the console and comparing method names against the official Three.js documentation before committing to a direction.
